# Rust port: copy-on-write performance design and Go aliasing ledger

Produced by the cow-perf-design audit (4 audits, 3 adversarial reviews, 1 synthesis) on 2026-11-17.
The rules live in rust/PORTING.md section 7. This file records the decisions, the deterministic Go
aliasing behaviours later tiers must port as named seams, and the per-tier rules for unit prompts.

## Decisions

- Every Go pointer-to-struct field, generated or hand-written, is Option<Arc<T>>, with no per-type Box override; typegen's `inline` override stays for holding a struct by value. One representation keeps ports mechanical, and on synth12 the prototype cut clone allocations from 625 to 186 and per-bidder copy allocations from 637 to 198, with decode and encode unchanged.
- Writes go only through Arc::make_mut, at Go's write point and after Go's condition, with the ptrutil::make_mut and make_mut_or_default helpers. make_mut copies exactly when another holder exists, so value semantics cost no extra copies; a speculative call is the only way to waste one.
- Slices stay Option<Vec<T>>, maps stay Option<BTreeMap<K,V>> and strings stay String; Arc<[T]> and Arc<str> are deferred to a measured follow-up. clippy::rc_buffer forbids Arc<Vec> and Arc<String>, Arc<[T]> needs new gojson impls including the hidden option/slice hooks, and the remaining per-bidder cost (198 allocations against Go's 70) is Strings and Vecs that must be profiled first.
- BidRequest.imp stays an owned vector. Go builds a fresh imp slice per bidder (splitImps) and rewrites each imp's ext, so sharing the vector buys nothing; the imps' media objects are Arc-shared.
- The endpoint owns the RequestWrapper and lends &mut through HoldAuction; per-bidder requests are owned values, and Arc is used only for immutable sharing. A single writer needs no locks and mirrors Go's ownership.
- The RequestWrapper is ported literally: ext caches with their dirty flags, and imp wrappers with their accessed flag, are wrapper state independent of the pointee. Go's output depends on stale caches: buyeruids written over the FPD user.ext, and stored-response imps restored.
- Arc::ptr_eq stands for Go identity only where Go's copy points are mirrored; elsewhere explicit markers are used, as for eids. Rust shares where Go deep-copies (ortb.Clone*), and Vec and BTreeMap have no identity.
- Every deterministic Go aliasing behaviour becomes a named seam with a Go golden: the ledger, the eids marker, the untracked prebid write, late binding. Arc sharing cannot express write-through, and relying on it implicitly would be untestable.
- Writes through objects that bidders share with the auction request go through a per-auction shared-write ledger. It is replayed on the auction request after getAllBids in both modes, and on later bidders in parity mode. The write-back is deterministic in Go because getAllBids waits for every bidder; the cross-bidder leak is deterministic only under the parity harness's bidder_request_phase order.
- Production Rust runs bidder request phases concurrently and never shows one bidder's write to another (the writer-last schedule). Serializing the phases would cost latency, and this outcome is one Go can produce.
- Go nondeterminism is resolved by the pbs-parity fakes.json orders, or else by ascending keys, and is never emulated. Determinism makes differential testing possible, and any order Go can take is parity.
- The response bid graph is an arena with typed indices. Go keys maps by *Bid and *SeatBid pointers and compares pointers (winners, targeting, events, category dedupe); indices give that identity without Rc<RefCell>.
- Adapters get &mut BidRequest, and the exchange reuses the same value afterwards. Go passes the pointer and reads it back (MakeBids, X-Prebid, cur, the imp-group adapters).
- Hook bodies read an Arc snapshot taken at their group's start; mutations apply to the owner through &mut in plan order; replacing the payload in a discarding stage is a no-op. This matches Go's executor, and lets timed-out bodies that keep running detached own their input.
- Analytics, debug and video objects bind the final owner at log time. Go stores pointers (ao.RequestWrapper, ao.Response, vo.VideoRequest) and logs after later in-place changes.
- Refreshed shared state is read via ArcSwap (or a RwLock<Arc<T>> cloned and released), and process-wide values Go writes per request stay shared cells. That costs one atomic load per request and keeps Go's cross-request side effects (BannerCreativeMaxSize, flipp) observable.
- RawJson stays Option<Arc<[u8]>>. Its clone is already a refcount bump, and a Bytes-backed type would ripple through every crate for no measured gain.
- pbs-gojson keeps its Box impls beside the new Arc impls. Hand-written types and the existing goldens use them, so removing them would be churn.
- Typegen refuses embedded pointer-to-struct fields. Go's MergeClone writes through them into the shared original (its dereferenceDecoder is not decorated), and copy-on-write would silently change that; no such field exists today.
- jsonutil::merge_clone_fields ships in T2b. The eids identity seam must know which fields Go's MergeClone replaced, and only the decoder knows (jsoniter's case-insensitive field binding rules out a pre-scan); T2b owns pbs-gojson.
- A Go-append model is used only for the ExtBidResponse errors pair. It is the only verified deterministic append aliasing, and a general Go-slice type would tax every port.
- Benchmarks are criterion plus dhat in benches/, with paired Go benchmarks and a Box baseline recorded before the switch. unsafe is forbidden, so a custom counting allocator is impossible, and the change must be proven by numbers.
- T2b makes no global allocator change; mimalloc or similar is evaluated in the server tier under load. The allocator is a process-wide choice and must be measured in situ.
- The account cache stores the account once per id, after UnpackDSADefault and setDerivedConfig, as Go's newAccountTransform does. Memoizing at any other point changes the DSA defaults that requests see.

## Go aliasing behaviours to port as named seams

### exchange/utils.go:156 and 270-303 (fpdUserEIDExists); firstpartydata/first_party_data.go resolveUser (ptrutil.Clone + MergeClone); exchange/utils.go:1069-1078 (applyFPD)

- Go: A bidder's FPD user eids count as present unless they are the very array of the request user's eids; Go compares &reqUserEIDs[i] with &fpdUserEIDs[i]. They are the same array in two cases: resolveUser's shallow user copy kept EIDs because MergeClone did not decode `eids`; or applyFPD stored reqWrapper.User.EIDs into the shared FPD entry while removeUnpermissionedEids had kept the original array. The difference only matters when both lists are non-empty and of equal length.
- Rust: An explicit marker on the resolved FPD user (eids_alias_request). resolveUser sets it to (request user non-nil and `eids` not in jsonutil::merge_clone_fields' result). applyFPD's write sets it to whether removeUnpermissionedEids returned early. fpdUserEIDExists first applies Go's length rules, then returns !marker when the lengths are equal and non-zero. The check looks up the raw bidder key, while applyFPD uses the core name or alias, as in Go. Golden: FPD eids equal by value to the request's, under alias and core keys.

### exchange/utils.go:621-644 (extractAndCleanBuyerUIDs), :157 (CloneAndClearImpWrappers), applyFPD, :416 (RebuildRequest in applyPrivacy); openrtb_ext/request_wrapper.go:426-444, 710-745

- Go: extractAndCleanBuyerUIDs clears user.ext.prebid.buyeruids through a shallow GetPrebid copy plus SetPrebid, which dirties the auction request's userExt cache. Every bidder wrapper inherits the dirty cache. applyFPD swaps in the FPD user without invalidating the cache, so the rebuild overwrites the FPD user's ext with the cached request user.ext.
- Rust: Ext caches and dirty flags are wrapper state, and replacing rw.user never resets them. CloneAndClearImpWrappers copies them with their flags. RebuildRequest writes the cached ext into whatever User is present, using make_mut. Golden: buyeruids plus a bidder FPD user.ext.

### privacy/scrubber.go:77-87 (ScrubTID); exchange/utils.go:217-219 and 306-319 (removeImpsWithStoredResponses), :232 (RebuildRequest)

- Go: ScrubTID goes through GetImp/SetImp, which leaves the bidder's imp wrappers accessed. removeImpsWithStoredResponses then assigns req.Imp directly. The final RebuildRequest rebuilds from the stale wrappers and restores the removed imps, whether or not ConvertDownTo25 ran.
- Rust: Imp wrappers and their accessed flag stay independent of rw.imp, and a direct imp write leaves them in place. rebuildImp reproduces Go's arrays. Golden: transmitTid denied plus a stored bid response.

### openrtb_ext/request_wrapper.go:84-88 (GetImp: &rw.Imp[i]), SetImp, rebuildImp

- Go: Wrapper writes land in the imp array the wrapper was built over. SetImp copies into a new array. rebuildImp writes the rebuilt imps into the old array and then copies them, so holders of the old array (shallow request copies) see the rebuild.
- Rust: Wrappers are bound to the wrapper's imp vector by index, so reads while bound see wrapper writes. SetImp detaches them, each keeping its own Imp. Holders of the old array are modelled where they exist (the analytics clone case).

### floors/floors.go ~56-110 (updateBidRequestWithFloors); floors/validate.go:37-54; createFloorsFrom with openrtb_ext/floors.go:105-124 (Copy); floors/floors.go:229-239 (updateFloorsInRequest)

So the normalised map reaches req.ext.prebid.floors via SetPrebid+RebuildRequest, but the default Delimiter, set on the local copy, does not.

### bidadjustment/build_rules.go:56-101 (merge, mergeForMediaType); openrtb_ext GetPrebid (shallow); surfaced at floors/enforce.go:78+36 and analytics/build/build.go:196-197

- Go: merge writes extPrebid.BidAdjustments.MediaType.* through the pointee that GetPrebid's shallow copy shares with the cached prebid, without calling SetPrebid. The cache changes untracked. The merged adjustments reach req.ext only when a later SetPrebid+RebuildRequest marshals the cache.

### adapters/gumgum/gumgum.go:25-48 (siteCopy = *request.Site; siteCopy.Publisher.ID = ...); parity-harness branch exchange/parity_turns.go and exchange/exchange.go:791, 797 (bidder_request_phase)

- Go: gumgum copies the Site but not its Publisher. The Publisher stays shared with the auction request and with every bidder request that did not fork it (FPD that decodes `publisher` forks it). The pub ID always reaches the auction request, where analytics sees it. Other bidders see it only racily. Go's parity mode makes it deterministic for bidders after gumgum in name order.
- Rust: Shared-write ledger (exchange::aliasing). gumgum's Publisher.ID write goes through ledger.write. The identity is the auction request's Publisher Arc registered at the split, or a version the ledger handed out. The write is applied to the auction request right after getAllBids in both modes, with writes in bidder name order. In parity mode it is also applied to each later bidder's request at the start of its turn, and the request phases run one at a time in name order, like Go's parityTurns.

### adapters/richaudience/richaudience.go:34 and 207-216 (getIsUrlSecure sets request.Site.Domain before the per-imp Site copy at 63-66)

- Go: When site.domain is empty and site.page parses, richaudience writes the page host into the Site it shares with the auction request and the other bidders.
- Rust: The same ledger, keyed by Site identity. The write keeps Go's condition (domain empty), evaluated on the writer's view. So in parity mode a later richaudience alias sees the replayed domain and skips the write.

### modules/prebid/ortb2blocking/hook_bidderrequest.go:506-546 (createBAttrMutation, createBTypeMutation), hook-body presence checks at :150, :186, :210, :234; exchange/utils.go splitImps (impCopy := imp)

## Rules for later tiers

- [all] Pointer-to-struct fields are Option<Arc<T>>. Read through as_deref(). Write only with Arc::make_mut or pbs_util::ptrutil::{make_mut, make_mut_or_default}, at Go's write point and after Go's condition. Never call make_mut to read, speculatively, or to store an unchanged value. Clone with Arc::clone(&x); move out with Arc::unwrap_or_clone.
- [all] Port a Go copy (c := *p; q = &c, ptrutil.Clone, ortb.Clone*) as an Arc clone at the same program point, and Go's later writes to the copy as make_mut writes. The exchange's shared-write ledger tracks Site, Site.Publisher and imp Banner/Video/Audio objects. For these, a Go copy that is stored without being written is Arc::new((*p).clone()) at that point, so that Arc identity keeps matching Go's.
- [all] Port every deterministic Go aliasing behaviour (a write one holder makes and another reads later, or a pointer or slice-element comparison) as a named seam: an item named after the Go behaviour, a // Go: citation, a test reproducing Go's output, and an entry under `# Go aliasing` in the crate docs. Never rely on Arc sharing to reproduce it. Where Go shares, never assume value semantics without checking who reads later.
- [all] Arc::ptr_eq means Go identity only under PORTING §7's conditions (mirrored copy points). Never use it after an ortb.Clone* port, and never for Vec or map identity. Use explicit markers instead, for example markers built from jsonutil::merge_clone_fields.
- [all] Resolve Go nondeterminism (map range, goroutine completion, data races); never emulate it. Use the order that pbs-parity's contract/fakes.json `orders` names: bidder_request_phase, fpd_bidders, bidder_response_order, bidder_params_validation, stored_bid_responses_validation, alias_validation, alias_gvlid_validation, bid_adjustment_factors_validation, auction_winners, category_dedupe, and the six adapter imp-group orders. Otherwise use ascending keys (BTreeMap order or pbs_parity::fakes::map_keys). Cite the choice at the site. Parity mode imposes exactly the orders Go's parity mode imposes.
- [all] Process-wide state that Go writes at runtime stays process-wide. Two known cases are the exchange's BannerCreativeMaxSize (exchange/exchange.go:535, config/config.go:742-746) and flipp's package variable of imp params (adapters/flipp/flipp.go:37). Both are shared cells, written and read where Go does. Any newly found package variable written per request follows the same rule.
- [all] Goroutines become Tokio tasks that own their inputs (Arc snapshots or owned requests). Snapshots are one-level clones with Arc-shared children, never deep copies. Keep them short-lived, because while a snapshot is alive every later make_mut copies.
- [all] Every hot path a unit ports gets a criterion bench, plus a paired Go bench under testdata/go when the unit claims speed against Go. Report before and after numbers in the commit message.
- [request-wrapper] Ext caches with their dirty flags, and imp wrappers with their accessed flag, are wrapper state independent of the current pointee. Replacing rw.user, device, site and so on never invalidates a cache. The next RebuildRequest writes the cached ext into whatever object is present: utils.go:416 overwrites the FPD user.ext with the ext cached when extractAndCleanBuyerUIDs dirtied it (utils.go:621-644). CloneAndClearImpWrappers (request_wrapper.go:426-444) copies the caches with their flags and clears the ORIGINAL's accessed flag. Clone (404-424) is test-only: do not port it.
- [request-wrapper] GetImp binds wrappers to the current imp array (Go: &rw.Imp[i], request_wrapper.go:84-88), and SetImp installs a new array. A direct write of rw.imp (removeImpsWithStoredResponses, exchange/utils.go:306-319) leaves the accessed wrappers in place, so the next RebuildRequest (utils.go:232) restores the wrapped imps. Reproduce this; do not fix it. Golden: transmitTid denied plus a stored bid response.
- [request-wrapper] GetPrebid returns a shallow copy that shares the cached prebid's pointees, so a write through such a pointee without SetPrebid is untracked. Port this as a dedicated RequestExt::prebid_mut_untracked() with no dirty flag. Only bidadjustment merge (bidadjustment/build_rules.go:56-101) uses it. The write then surfaces only at the next SetPrebid+RebuildRequest (floors/enforce.go:78 and :36, analytics/build/build.go:196-197).
- [exchange] HoldAuction takes &mut RequestWrapper. cleanOpenRTBRequests builds each bidder request as an owned one-level BidRequest clone (exchange/utils.go:157-159). Its imps come from splitImps: Imp clones sharing the media Arcs, with mergeImpFPD through jsonutil::merge_clone (utils.go:654-717). Keep Go's per-bidder step order: fpdUserEIDExists, CloneAndClearImpWrappers, schain, removeUnpermissionedEids, buildRequestExtForBidder, floors adjustment, prepareUser, privacy block, applyFPD, applyPrivacy (CloneBidRequestPartial, scrubbers, RebuildRequest), GPP legacy fields, removeImpsWithStoredResponses, CloneRegs+ConvertDownTo25, RebuildRequest.
- [exchange] Build one shared-write ledger (exchange::aliasing) per HoldAuction. (1) At the split, register the Arcs of the auction request's Site, Site.Publisher, and each imp's Banner, Video and Audio. (2) Three known writers write through these objects: gumgum Site.Publisher.ID (adapters/gumgum/gumgum.go:45-46), richaudience Site.Domain (adapters/richaudience/richaudience.go:34, 207-216), and ortb2blocking BAttr/BType (modules/prebid/ortb2blocking/hook_bidderrequest.go:506-546). Each such write goes through ledger.write(slot, write). (3) ledger.write resolves the slot's Go identity: Arc::ptr_eq to a registered original, or to a version the ledger handed out. Unregistered objects, such as FPD forks, record nothing. It then applies the write with make_mut and records (identity, bidder, field write). (4) ledger.apply(&mut BidRequest) replays the recorded writes, in order, onto every slot of that identity. (5) Apply the ledger to the auction request right after getAllBids, in both modes, with writes ordered by bidder name. In parity mode, also apply it to each bidder's request at the start of its turn. The ledger holds Arc clones of the originals, so their addresses are never reused.
- [exchange] Parity mode only (a parity case in flight, at least two bidder requests, unique bidder names): bidders build their requests one at a time in bidder name order, like Go's parityTurns/parityTakeTurn (parity-harness branch: exchange/parity_turns.go; exchange/exchange.go:791, 797). A turn covers the bidder-request hook stage through MakeRequests. It ends when MakeRequests returns or the bidder task ends, and waiting stops at the auction deadline. HTTP calls and MakeBids stay concurrent. In production the phases run concurrently, and other bidders never see a writer's ledger writes. This is the writer-last schedule, which Go can also take.
- [exchange] requestBid (exchange/bidder.go:179-345) runs in this order: a new wrapper over the bidder request; bidder-request hooks; RebuildRequest (195); tmax; MakeRequests (206) with &mut of that request; X-Prebid built from the mutated request (215); headers cloned per request (217-222); one request inline, otherwise one task per request, with stored responses after. Then, per response: MakeBids (306); raw-bidder-response hooks; an empty cur set to USD after the first MakeBids (319-321); currency conversion; addNativeTypes when an App is present. Responses arrive in call order (bidder_response_order). A bidder panic runs the deferred RecordAdapterRequest before the recover (per review 3; verify).

## Risks

- The RequestWrapper imp-wrapper binding (bound, or detached after SetImp) is the subtlest port. A mistake silently changes which imps a rebuild writes. Golden: transmitTid denied plus a stored bid response.
- A speculative make_mut (called before testing Go's condition, or just to read) silently copies a whole struct. Only benches and review catch it.
- ptr_eq used outside the mirrored-copy conditions reproduces the wrong Go identity: after an ortb.Clone* port, or on objects Rust shares lazily where Go copied. Keep ptr_eq inside named seams.
- Long-lived snapshots keep refcounts above one, so later writes copy. Examples are detached timed-out hook bodies, analytics clones and parity traces. The cost is extra copies, not wrong output; keep snapshots short-lived.
- The Box and Arc impls do not forward the hidden option/slice hooks of pbs-gojson's traits. That is correct for structs, but it blocks Arc<[T]> and Arc<str> until dedicated impls exist.
- In-flight branches keep adding Box idioms (as_deref_mut, Box::new) until T2b starts. T2b must start after all merges, then regenerate and fix up. Any branch that lands later conflicts.
- About 149 generated fields change type. Downstream code and unit prompts written against Box idioms must switch to the step-6 table; a stale prompt template will reintroduce Box code.
- The seams change observable output only in corner cases, such as analytics objects and parity-mode bidder requests. Without the listed goldens, a missed seam shows up only in live traffic.
- The Rust exchange needs the bidder_request_phase turns and the ledger in parity mode. Without them, the Go/Rust parity runner reports gumgum, richaudience and ortb2blocking mismatches. Residual races remain (b) and may need a harness exclusion, for example a bidder before the writer reading the shared object in MakeBids.
- criterion and dhat may add duplicate crate versions, which clippy::multiple_crate_versions (cargo group, -D warnings) rejects. criterion's macros may also trip missing_docs or other lints. Fall back to unified versions, a hand-written main, or a std::time harness; never suppress.
- Disk space: criterion output and per-unit target dirs are large. Use a CARGO_TARGET_DIR outside the repo and delete it afterwards.
- arc-swap is a new dependency the orchestrator must approve. The fallback, RwLock<Arc<T>>, costs a lock per read.
- Bench noise on a shared laptop can hide or fake gains. Compare medians with criterion's confidence intervals, run each layout twice, and report both.
- The Go corpora's requests are small (the largest is 2.1 KB), so the claimed gains rest on synthetic fixtures. Confirm them with exchangetest and end-to-end load in later tiers.
- Arc refcount traffic crosses cores when many bidder tasks clone the same children. It is usually negligible; measure it in the server tier.
- Some inputs were taken from audits and reviews, not re-checked here: the Go benchmark numbers, and the review-3 claims about channels, logging, deadlines and background first runs. Verify them before relying on them. The server timeout claims were verified in the Go source.
